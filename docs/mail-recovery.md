# 6번 작업: 메일 발송 결과 확인·복구 — 2026-10-11

> 환경 구분: 이 문서의 2026-10-10~11 작업·시험·계정 상태는 기존 Mac 개발 이력입니다. Ubuntu의 현재 상태는 [Mac·Ubuntu 환경 구분](development-environments.md)을 따릅니다. 역사적 `outputs/` 증빙과 `.work/` 백업·비공개 자료는 이 저장소 및 확인한 Ubuntu 작업 폴더에 미포함이며 원문은 미확인입니다.

## 구현

6번 운영 준비의 메일 오류 처리 항목을 개발 환경에서 보완했다. 실제 회사 기능 검수·오픈은 미실시다. 실제 접수 잠금은 유지한다.

확인 메일의 시간 초과·모호한 응답·중단된 발송 lease는 unknown_at을 기록하고 자동 발송 대기에서 제외한다. 발송 전 암호문 오류는 요청을 보내지 않고 실패 처리한다. 명확한 미수락 응답만 1분·5분·30분·2시간 간격/총 5회 제한 내에서 동일 이벤트로 재시도한다. 만료·무효 링크의 암호문은 정리한다.

별도 선택 바인딩 INQUIRY_MAIL_STATUS가 읽기 전용 결과 조회를 담당한다. 미연결 또는 응답 불명일 때는 재발송하지 않는다. 확인 메일 불명 결과는 정기 작업에서 5분 간격으로 최대 3건씩 조회한다. 수락 영수증 확인 시 서비스 접수로 기록하고 암호문을 제거한다. 확실한 미수락만 유효 링크의 재시도를 허용한다. 만료·철회 또는 시도 제한 도달 시 재시도하지 않는다.

문의 상세에서 업무 안내와 고객 확인 메일 상태를 구분한다. 문의 직원은 결과 불명 업무 메일의 ‘제공자 발송 결과 확인’을 사유와 함께 실행한다. 콘텐츠 직원은 접근할 수 없다. 조회 중 권한 회수·문의 버전 또는 메일 상태 변경 시 변경을 거절한다. 확정 결과는 처리·감사 이력에 남긴다. 조회는 메일을 발송하거나 사이트 답변·견적을 다시 만들지 않는다. 서비스 접수는 고객 수신·열람 완료가 아니다.

## 내부 제공자 조회 계약

실제 서비스 선정 후 어댑터가 구현할 내부 계약이며 외부 제공자 연결 완료를 뜻하지 않는다. INQUIRY_MAIL_STATUS는 환경변수가 아닌 신뢰하는 Workers 서비스 바인딩이다.

GET https://mailer.internal/v1/status?eventId={인코딩한 기존 이벤트 ID}

고객 이메일·문의 본문·링크·토큰은 조회에 보내지 않는다. 성공 응답은 반드시 동일 eventId를 포함한다.

- 수락 확정: HTTP 성공과 {"eventId":"동일 ID","state":"accepted","receipt":"비어 있지 않은 200자 이하 영수증"}.
- 미수락 확정: HTTP 성공과 {"eventId":"동일 ID","state":"rejected","definitive":true}. 해당 요청이 수락되지 않았고 이후에도 발송되지 않을 것이라는 제공자 증거가 있어야 한다.
- 조회 없음·지연·없는 ID·불일치 ID·잘못된 영수증·반송·시간 초과·미확정 미수락은 unknown이다. 반송이나 조회의 not-found를 재발송 근거로 쓰지 않는다.
- 어댑터는 발송 이벤트/중복 방지 키와 제공자 기록을 연결한다. 미수락 확정을 보장하지 못하는 제공자는 definitive:true를 반환하면 안 된다.

전체 자동 테스트 106개·타입 검사·배포 전 빌드 통과. 이번 8개 신규 시험은 불명 결과 반복 발송 차단, 중단 lease, 수락 영수증, 동일 이벤트 재시도, 철회 인증 차단, 모호한 조회·조회 간격, 명확한 거절·손상 암호문, 관리자 권한·동시 상태 변경·감사 사유를 검증한다.

## 6번의 남은 항목

실제 제공자 조회·반송 수신·운영 책임자 실패 알림 연결, 승인 보관 기준·보관 예외·영구 삭제·삭제 대장·백업 복원, 고객 추가 첨부·검토 요청·목록 페이지, 외부 서비스 연결과 회사 업무 검수가 남아 있다. 확인 요청/발송 대기 기록은 기존 만료 24시간 후 정리 규칙을 유지한다. 장기 결과 대장과 불명 기록 보관은 승인 기준에 맞춰 별도 보완해야 한다. 이번 작업으로 6번 전체 완료나 운영 검수 통과를 표시하지 않는다.
