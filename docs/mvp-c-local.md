## 사용자 선택과 계정

이메일·비밀번호로 로그인한다. 최초 책임자의 표시 이름은 ‘책임자’로 확정했다. 별도 콘텐츠 직원의 이름·이메일도 사용자에게 확인했으며 콘텐츠 관리 권한만 부여한다. 계정 이메일과 대기 초대 자료는 공개 문서 대신 프로젝트 `.work/c-local/confirmed-staff.json`에 비공개로 보관한다.

최초 책임자는 로컬 오프라인 명령으로 **초대 중** 상태에만 등록했다. 비밀번호·활성 세션을 대신 만들지 않았다. 책임자가 초대 링크에서 직접 비밀번호를 설정해야 최초 로그인이 가능하다. 콘텐츠 직원은 책임자 활성화 후 직원 계정 관리 화면에서 초대한다. 자동 메일은 연결하지 않았으며 초대·재설정 링크는 책임자가 직접 전달한다.

초대는 48시간, 재설정은 1시간 동안 한 번만 사용 가능하다. 책임자만 직원 본인 확인 체크와 사유를 남겨 재설정 링크를 발급한다. 새 링크 발급은 이전 미사용 재설정 링크를 회수하며, 비밀번호 설정 성공 시 기존 세션을 모두 회수한다. 중지된 계정은 링크 사용과 로그인 모두 불가능하다. 비밀번호는 최소 15자, 최대 256자로 입력하며 원문을 저장하지 않고 별도 무작위 salt와 PBKDF2-HMAC-SHA256 600,000회 결과를 저장한다. 로그인 요청에는 계정별·접속별 제한을 적용한다.

기존 콘텐츠·문의·책임자 권한, 최신 계정 상태 확인, 마지막 활성 책임자 보호를 재사용한다. 전용 비밀번호 환경에서는 기존 OIDC 로그인 시작·콜백을 제공하지 않는다. 기존 OIDC 시험 코드는 회귀 시험을 위해 보존했다.

## 실행과 주소

기존 공개 미리보기는 `http://127.0.0.1:8787`을 유지한다. 직원 로그인 시험은 `https://localhost:8788/admin/login`이다. 정확한 주소를 사용해야 로그인·저장 요청의 출처 확인을 통과한다.

개발용 인증서는 localhost와 127.0.0.1만 대상으로 만들었고 30일 유효하다. 시스템 인증서 신뢰 저장소를 변경하지 않았다. 브라우저에서 개발 인증서 확인 화면이 나타날 수 있다. 운영 도메인의 인증서·운영 배포가 완료된 상태는 아니다. 비밀 설정과 개인키는 Git에 포함하지 않는다.

작업 폴더 `website`에서 별도 터미널로 다음을 실행한다.

```sh
pnpm scanner:local
pnpm dev:https
```

기존 미리보기의 실행은 `pnpm dev`다. `pnpm setup:check --password-local`로 선택한 환경의 설정과 책임자 초대 상태를 읽기 전용으로 확인한다. 최초 초대 원문은 `.work/c-local/initial-admin-invitation.json`에만 보관한다. 오래된 초대 재발급은 `auth:initial-local --reissue --password-local`의 오프라인 절차를 사용하며 현재 이름·이메일·확인 여부는 표준 입력으로 전달한다. 비밀번호나 링크 원문을 검증 문서에 붙이지 않는다.

## 실제 파일 검사

ClamAV 1.5.4 공식 macOS 패키지의 Apple 서명·공증을 확인한 뒤 프로젝트 내부에 풀었다. 시스템 경로에 설치하지 않았다. 내부 경로에서 실행하기 위해 실행 파일의 라이브러리 검색 경로를 추가하고 로컬 ad-hoc 서명을 적용했다. 원본 서명된 패키지를 비공개 작업 폴더에 보존했다. 공식 main/daily/bytecode 정의 파일을 FreshClam으로 내려받아 검증했다.

검사 서비스는 127.0.0.1:8790에서만 받으며 비공개 공유 키가 필요하다. 앱은 내부 `FILE_SCANNER` 바인딩→로컬 어댑터→별도 검사 프로세스를 호출한다. 업로드 파일을 외부 파일 검사 서비스로 전송하지 않는다. 정의 파일 업데이트에는 인터넷을 사용한다. 서비스 실행 시와 이후 하루마다 업데이트를 시도하며 daily 정의 파일이 48시간을 넘으면 성공 판정을 제공하지 않는다.

원본과 재처리 결과를 각각 실제 엔진으로 검사한다. Pillow로 JPG·PNG·WebP를 디코딩·재인코딩해 EXIF·위치·텍스트 등 원본 메타데이터를 제외한다. pikepdf로 PDF 구조를 확인하고 암호화·자동/클릭 실행 동작·JavaScript·첨부 파일·폼·외부 링크 등을 거부한다. PDF 문서·XMP 메타데이터도 제거한다. 결과는 기존 계약대로 원본 크기 이하여야 하며, 검사 완료만으로 공개 콘텐츠에 자동 연결하지 않는다.

최대 입력 20MiB·사진 40메가픽셀, PDF 500페이지·100,000 객체, 순차 검사, CPU·실행 시간·파일 크기 제한을 적용한다. 공식 정의 파일을 읽는 엔진의 정상 실행에서 약 1.6GiB 사용을 측정했으며, 서비스는 검사 프로세스 그룹의 실제 메모리 사용량을 주기적으로 확인해 2GiB 초과 시 중단한다. 운영용 컨테이너 격리와 강제 자원 제한·배포 방식은 추후 확정해야 한다. 이 로컬 구성은 운영 배포 승인을 뜻하지 않는다.

정상 판정이 완전한 경우만 새 안전 객체를 만들고 현재 작업 lease를 확인해 ready로 전환한다. 차단은 422, 엔진·정의 파일·검사 프로세스·연결 오류는 503으로 처리한다. 오류나 불완전한 판정은 검사 성공으로 표시하지 않는다. 실제 고객 접수 잠금은 유지한다.

## 검증 구분

자동 시험·브라우저 시험은 격리한 시험 계정과 메모리 DB를 사용한다. 실제 책임자 비밀번호를 만들거나 실제 회사 콘텐츠를 등록하지 않는다. 브라우저에서 초대 수락·비밀번호 설정·로그인·로그아웃·콘텐츠 권한 분리·모바일 화면을 확인한다. 파일 통합 시험은 모의 검사기 대신 실제 workerd 서비스 바인딩·어댑터·ClamAV와 공식 정의 파일을 사용하며 사진/PDF 성공·차단과 새 객체 생성까지 확인한다.

EICAR는 실행 가능한 악성 프로그램이 아닌 표준 검사 시험 문자열이다. 시험에서 원문 문자열 파일을 PDF 형식으로 선언해 검사기의 원본 악성코드 판정과 거부를 확인한다. PDF 메타데이터 안에 이 문자열을 인코딩해 넣는 것은 표준 EICAR 파일과 다르므로 같은 탐지를 가정하지 않는다.

검증 자료: 프로젝트 루트 `outputs/검증/20261011-mvp-c-local/`. 실제 책임자 설정·실제 직원의 초대 수락·회사 파일 업로드와 업무 검수는 사용자 참여 후 별도로 기록한다.

기술 기준: [OWASP 비밀번호 저장](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [Cloudflare Node Crypto](https://developers.cloudflare.com/workers/runtime-apis/nodejs/crypto/), [로컬 복수 Worker](https://developers.cloudflare.com/workers/local-development/multi-workers/), [ClamAV 공식 배포](https://www.clamav.net/downloads), [pikepdf 구조 검사 API](https://pikepdf.readthedocs.io/en/latest/api/main.html).


## 2026-10-11 개발 비밀번호 선택 반영

사용자 요청으로 최초 책임자 계정의 짧은 개발 비밀번호를 실제 로컬 HTTPS 환경에 설정했고, 초대 링크를 소비하여 계정을 활성화했다. 비밀번호 평문은 문서에 기록하지 않는다. `STAFF_DEV_SHORT_PASSWORD=true`는 비공개 로컬 설정에만 적용한다. HTTPS localhost/127.0.0.1에서만 최소 4자를 허용하며 기본 정책은 최소 15자다. 15자 미만 자격 증명에는 DB `local_only` 표시를 보관한다. 개발 예외를 끄거나 외부 주소로 옮기면 해당 자격 증명의 로그인과 기존 세션이 거부된다. 정상 길이 비밀번호로 재설정하면 개발 제한 표시가 해제된다.

검증: 자동 시험 122개 통과, 타입 검사 및 배포 없는 빌드 통과. 실제 책임자 계정 활성화와 관리자 화면 접근(200)을 확인했다. 콘텐츠 직원 김관리의 초대·비밀번호 설정은 후속 진행 대상이며 실제 고객 접수 잠금은 유지한다. 이전 기록의 ‘책임자 초대 상태/미설정’은 이 작업 전 상태다.
