## 현재 상태와 변경

직원 인증 제공자·클라이언트 등록·HTTPS 시험 주소, 파일 검사 서비스는 미정이다. 최초 관리자 지정 정보는 기존 비공개 작업 자료만 유지하며 공개 문서/점검 출력에 개인 이메일을 넣지 않는다. 실제 직원 등록·서비스 생성·배포·비밀값 설정은 하지 않았다. 실제 접수와 직원 로그인 잠금 유지.

`pnpm setup:check`는 .dev.vars 설정, wrangler 서비스 바인딩 선언, 로컬 DB의 책임자/파일 검사 작업 상태를 읽기 전용으로 확인한다. 이메일·issuer 주소·client ID/비밀값·서비스 식별자·쿠키·토큰·저장 키를 출력하지 않는다. JSONC 주석과 후행 쉼표를 처리하며 설정 값 안의 URL/문자열을 보존한다. 설정 완료/바인딩 선언을 실제 연결 검수 성공으로 표시하지 않는다. DB 후보가 불명확하면 등록하지 않고 확인 불가로 보고한다.

파일 검사 응답 판정을 별도 함수로 통일했다. 계약·구조·악성코드 판정·MIME·실제 길이 헤더·엔진 식별·이미지 재인코딩/치수·PDF 안전 판정이 모두 유효해야 처리한다. 빈 엔진, 지수 표기 길이/치수, 미확정 악성코드 결과, 과대 이미지·원본보다 큰 결과, 안전 판정 없는 PDF는 ready로 전환하지 않는다. 기존 바이트/서명 재검사와 현재 lease 확인, 역할 분리·비공개 격리 흐름은 유지한다. 이것은 실제 검사 엔진이 아니며 악성코드 없음 자체를 판정하지 않는다.

## 연결에 필요한 입력

| 대상 | 회사가 확정할 정보 | 저장/처리 |
| --- | --- | --- |
| 직원 인증 | 사용할 서비스, 개인 계정, 초대 수락용 확인 이메일 클레임 지원 | 기존 docs/staff-auth-setup.md의 계약 적용 |
| 인증 앱 | issuer/client ID/client secret, 시험용 HTTPS origin | 실제 비밀은 .dev.vars/운영 비밀 설정; 채팅/문서/Git에 기재하지 않음 |
| 리다이렉트 | 확정 HTTPS origin + /api/staff-auth/callback | 제공자 앱에 정확하게 등록 |
| 최초 책임자 | 확인한 개인 이름/이메일과 계정 소유 확인 | 회사 확인 후 오프라인 최초 등록 명령의 표준 입력 |
| 파일 검사 | 실제 검사 서비스/엔진, 안전 이미지/PDF 처리·악성코드 계약 충족 | FILE_SCANNER 내부 서비스 바인딩; 공개 콜백/강제 ready 금지 |

HTTP 127.0.0.1:8787은 계속 공개 화면 미리보기다. HTTPS 검사를 낮추거나 모의 로그인/검사 기능을 실제 서버에 연결하지 않는다. 서비스 미정이면 이 문서와 도구로 준비 상태를 유지하며 실제 사용 가능으로 기록하지 않는다.

## 서비스 선정 후 실행 순서

1. HTTPS 시험 주소와 인증 제공자 앱을 등록하고 정확한 redirect URI를 설정한다. 해당 제공자가 현재 확인 이메일/서명/issuer/audience/nonce/PKCE 계약을 충족하는지 확인한다. 특정 서비스를 이 문서에서 대신 선택하지 않는다.
2. 비밀 설정 후 setup:check와 기존 auth:check를 실행한다. Discovery 확인은 계정 로그인 성공을 뜻하지 않는다.
3. 시험 DB를 백업하고 마이그레이션 확인 후 auth:initial-local --create에 확인된 개인 계정 입력을 표준 입력으로 전달한다. 수락 전은 invited 상태이며 active 세션이 없다. 초대 링크는 개인 계정에서 수락하며 원문을 검증 기록에 넣지 않는다.
4. 책임자→콘텐츠 직원→문의 직원의 실제 초대/로그인, 교차 접근 403·권한 회수·중지·로그아웃·만료·마지막 책임자 보호를 확인한다.
5. 계약을 실제 충족하는 검사 서비스 바인딩을 연결하고, 격리 시험 데이터로 사진/PDF 업로드→검사→ready→직원 연결→공개/비공개 다운로드를 시험한다. 검사 완료가 자동 공개를 뜻하지 않는다.
6. 잘못된 서명/구조·악성/암호화/실행 기능 PDF·과대 이미지·메타데이터 제거·서비스 지연/오류·중단 lease·권한 회수·숨김/차단 후 파일 회수와 재시도를 실제 검사 엔진으로 확인한다.
7. 실제 검수 결과·실패/수정·책임자 확인을 기록해야 C 실제 연결 완료로 표시한다. 접수 잠금은 D/E/F 필수 조건 충족 전 유지한다.
