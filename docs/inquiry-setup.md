실제 작업 폴더: `/Users/sminsiik/Documents/Codex/Project/gnc-cooling`. 사용자는 메일 서비스·회사 발신 주소를 아직 정하지 않았으며 개인정보 수집 안내도 미승인이라고 답했다. 따라서 현재 실제 접수는 닫혀 있다. 최초 직원 관리자 이메일을 회사 발신 주소나 고객 알림 수신자로 사용하지 않았다.

## 이번 구현

문의 종류(견적·상담/A/S), 요청 업무, 선택 업체명, 필수 담당자·전화·이메일·지역·본문, 선택 기존 설비·용량·치수, 동의 버전과 신청 당시 제품/모델/사례/사업분야 연결을 저장한다. 공개되지 않은 연결과 고아 모델은 거절하며 제목은 종류/업무로 자동 생성한다. 고객 회원 계정·비밀번호·내부 메모 입력은 없다.

개발용 접수 세션은 30분이며 쿠키는 Secure/HttpOnly/SameSite=Lax다. 출처와 CSRF 확인, 64,000바이트 입력 상한, 서버 Turnstile의 성공/hostname/action 확인 후 비공개 저장한다. 같은 세션·요청 ID·정규화된 내용의 재전송은 같은 최소 접수 결과를 반환한다. 다른 내용은409, 다른 세션에는 이전 접수 결과를 제공하지 않는다. 접수번호는 권한 증명이 아니다.

신청 상태(received/in_progress/completed/cancelled), normal/suspected/spam 분류, 이메일 확인, 파일 검사, 메일 발송은 독립적이다. 링크5개 이상 또는 긴 반복 문구/최근 동일 내용 반복은 의심으로 보존하는 개발 기준이다. 단어 한 개로 자동 스팸 확정·삭제하지 않는다. 의심 신청에는 최초 확인 메일을 보내지 않는다. 의심 복구/스팸 확정은 다음 문의 관리 단계에서 구현한다.

이메일 확인은 15분·단일 사용·해시 저장이다. 재발급은 같은 이메일/범위의 이전 미사용 링크를 폐기한다. 이메일의 앞부분·점·+별칭은 변경하지 않고 도메인만 소문자 처리한다. 목록 인증은 발급 당시 정상 문의 ID와 이메일 권한 버전의 범위를 보존하며 이후 접수 건을 자동 허용하지 않는다. 모든 조회/첨부에서 현재 이메일·권한 버전·확인·분류·삭제 상태를 재확인한다. 고객 세션은 최대2시간, 종료하면 삭제한다.

확인 링크의 토큰은 URL fragment에 담고 화면 진입 시 주소에서 제거한다. GET/HEAD는 토큰을 소비하지 않으며 명시적 버튼 POST로 확인한다. 이 화면에 외부 스크립트·분석 도구를 넣지 않는다. 접수/재발급 화면만 Turnstile을 사용한다. 확인 링크·쿠키·이메일·본문 원문을 로그로 출력하지 않는다.

## 외부 연결 규격

`CUSTOMER_ORIGIN`은 정확한 HTTPS origin이다. 직원 `APP_ORIGIN`과 별도이며 HTTP8787 공개 미리보기에서 실접수를 켜지 않는다. `INQUIRY_POLICY`는 회사가 승인한 `approved:true`, `version`, 전체 안내 `text`, `retention`, `contact` JSON이다. 동의 시 동일 버전/내용을 저장하며 활성 시험 환경의 개인정보 페이지도 이 안내를 표시한다. 회사 승인 내용을 임의로 작성하지 않았다.

`INQUIRY_RATE_SECRET`은 별도32자 이상 무작위 비밀값, `INQUIRY_MAIL_KEY`는 별도32바이트 AES-GCM 키(hex64자)다. Turnstile 키와 신뢰하는 `INQUIRY_MAILER` binding이 모두 있어야 한다. `INQUIRY_INTAKE_ENABLED=approved`는 수동 활성화 잠금이며 **현재 미설정 유지**. 이 값은 아래 잔여 작업·회사 검수 완료 전 운영에 입력하지 않는다. 필수값 누락 시 접수/API503, 내 문의401, 입력 없는 안내 화면을 반환하며 고객 데이터를 저장하지 않는다.

발송 서비스는 내부 `POST https://mailer.internal/v1/send`를 받는다. `Idempotency-Key`는 발송 기록 ID다. JSON은 `to`, `template:customer-verification`, `link`, `expiresAt`이며 발신 주소/실제 제공자 비밀값은 발송 서비스가 관리한다. 응답 `{accepted:true,receipt:"실제 제공자 접수 식별자"}`를 받아야 sent로 표시한다. 실제 받은편지함 도착을 보장하는 상태는 아니며 bounce/배달 확인 연계는 남았다. 시간 초과 재시도에서 동일 ID를 다시 전달하므로 발송 서비스도 중복 발송 방지가 필수다. 발송 대기 토큰/링크는 DB에서 AES-GCM 암호화하고 토큰 해시만 인증에 사용한다. 접수 저장과 발송 기록 생성은 동일 batch다.

예약 작업은 최대3건,2분 lease·30초 발송 제한으로 처리한다. 실패는1/5/30분/2시간 간격,총5회 이내 재시도한다. 다만 확인 링크는15분 만료이므로 만료 후 장기 재시도를 하지 않고 실패/재발급 대상으로 남긴다. 처리 로그/운영 실패 알림과 직원 신규 접수 알림은 후속이다. 비활성 중에도 만료 링크 암호문 정리와 만료 세션 정리를 한다. 확인 토큰/발송 기록은 만료24시간 후 정리한다. 문의 본문·동의·이력·연결 첨부의 영구 보관/파기는 승인 정책 확정 후 별도 구현한다.

## 반복 제한·첨부

이메일 접수3/10분, 네트워크 접수20/10분, 업로드 시작30/10분, 확인 요청/확정20/10분, 새 익명 세션60/10분이다. 메일은 동일 이메일/목적 범위당60초 간격, 이메일5/시간·10/일이다. HMAC 키만 저장하고 원 IP는 DB에 저장하지 않으며 제한 기록은 만료 후 삭제한다. 네트워크는 제한용일 뿐 정상 문의를 스팸으로 분류하는 근거로 쓰지 않는다. 실제 공유 인터넷과 장애 환경에서 조정/검수는 남았다.

첨부는 JPEG/PNG/WEBP/PDF,파일당10MiB·최대5개·합계30MiB다. 익명 세션 소유·inquiry 목적·30분 그룹/해시 일회 업로드 허가를 검사한다. 업로드 시작과 최종 제출의 Turnstile action/확인값을 분리한다. 검사 미완료/blocked 파일이 하나라도 있으면 제출을 보류한다. ready 파일만 문의에 원자적으로 귀속되며 같은 그룹을 다른 문의에 재사용하지 못한다.

내용 서명/실제 바이트 검사 후 [기존 내부 검사 계약](file-scanner.md)으로 별도 안전 파일을 만든다. 검사 서비스가 없으면 첨부 시작503/선택 비활성이다. 사진/PDF는 항상 private로 유지하고 공개 콘텐츠/콘텐츠 직원 경로에서는 제공하지 않는다. 인증 고객 다운로드도 현재 본인 문의 범위를 재확인한다. 미사용 그룹은 검사 완료 파일까지30분 만료 후 원본/안전 파일을 정리하며 제출된 파일은 승인 보관 정책을 따른다. 원본/파생 파일의 반복 삭제 실패 재시도·영구 보관/파기 이력은 후속이다.
