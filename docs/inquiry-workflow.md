## 답변·메모·고객 기록

고객용 답변은 작성 중 저장과 명시적 전달을 분리한다. 정상·이메일 확인 완료 문의만 전달할 수 있고 본문 또는 연결된 ready 첨부가 필요하다. 전달 본문은 직접 덮어쓰지 않으며 새 정정 초안으로 원문을 연결한다. 내부 메모는 별도 kind이며 고객 응답·파일·알림 본문에서 제외한다. 메모 원문은 그대로 두고 파일 연결만 변경할 수 있다. 첨부만 남기려면 빈 내부 메모 준비 기록을 먼저 만들고 검사 완료 파일을 연결한다.

미확인 정상 문의도 전화 상담·메모·상태 변경이 가능하다. 의심/스팸은 연락 정정·분류 검토·사유 있는 취소만 가능하며 일반 업무 진행·고객 전달은 정상 복구 후 수행한다. 정상 복구 이유를 기록하고 미확인 건은 설정/발송 한도 내 확인 메일을 준비한다. 이미 이메일을 확인한 의심 문의는 기존 본인 자료와 검토 안내만 볼 수 있고 일반 추가 제출/새 전달은 제한한다.

미처리는 특정 고객 message ID로 판단한다. 단순 화면 조회나 내부 메모 작성으로 처리하지 않는다. 답변 전달 때 대응한 ID들만 처리하거나, 전화 등 별도 처리 근거와 함께 명시적으로 처리 확인한다. 다른 문의 ID·이미 처리한 기록은 거절하며 동시에 들어온 새 기록은 남는다.

고객은 현재 본인 인증 범위에서 전달 답변·견적·안전 파일만 본다. 추가 설명은 원 신청을 덮어쓰지 않고 새 기록으로 저장하며 중복 제출을 방지한다. 본문 링크/반복 신호가 있으면 기록을 보존하고 의심 분류/직원 검토 알림으로 전환한다. 완료·취소 건에 추가해도 자동 재개하지 않는다. 현재 추가 설명은 텍스트만 지원하며 **고객 추가 파일 묶음 제출·의심 상태 고객의 제한된 검토 요청은 후속**이다.

고객 화면의 새 답변/견적 표시는 실제 전달 순번과 마지막 명시적 확인 위치를 비교한다. GET 조회만으로 읽음 처리하지 않는다. 화면에 제공된 순번만 POST로 확인하며 미래 기록을 확인할 수 없다. 현재 이메일/인증 버전별 위치를 보존한다. PDF를 제공한 이력도 남기지만 수신·계약/발주 확정으로 해석하지 않는다.

## 견적·비공개 파일

견적은 제목/안내와 회사 양식 PDF로 작성한다. 작성 중 기록을 만들고 PDF를 업로드/검사한 후 선택·저장·전달한다. 정상·확인 완료·현재 문의에 연결된 ready PDF만 전달된다. 첫 답변/견적 전달은 접수→처리 중으로 함께 바꾼다. 완료·취소 후 후속 전달은 해당 상태를 유지하며 재개는 이유와 함께 별도로 한다.

견적 버전 번호는 문의 내에서 자동 배정하고 새 전달 시 기존 최신본을 superseded로 보존한다. 두 직원의 동시 전달은 문의 버전과 최신본 UNIQUE 제약으로 최신본 하나만 남긴다. 잘못된 PDF/검사 중 파일은 기존 최신본을 바꾸지 않는다.

답변/메모 첨부는 JPEG·PNG·WEBP·PDF,각10MiB·5개·합계30MiB,견적은PDF1개20MiB다. 파일마다 문의/기록 목적·직원 소유·해시 일회 허가·30분 만료와 스트림 실제 크기/서명을 검사한다. 기존 [내부 검사 계약](file-scanner.md)을 통과해야ready가 되고 직원이 선택 저장해야연결된다. 실제 검사 엔진 없이는 validating을 유지한다. 미연결 답변/견적 파일은 제거 후 다시 선택할 수 있으며 전달된 파일은 이 경로에서 제거하지 않는다.

문의 파일은 항상 private다. 공개 콘텐츠/콘텐츠 직원 경로로 재사용할 수 없다. 문의 직원은 현재 권한·부모 미삭제·ready 조건으로 확인하며 고객은 같은 조건에 본인 범위와 답변/견적 전달 완료를 추가 검사한다. 내부 메모/초안/blocked/타 문의 파일은 고객에게 제공하지 않는다. 원본·이전 견적은 승인 보관 정책을 따른다. 영구 정리/삭제 재시도는 아직 구현 완료가 아니다.

## 상태·연락 정정·삭제

상태 네 가지와 본인 확인·분류·메일/파일 상태를 분리한다. 상태 변경·취소·재개에는 이유를 받는다. 담당자는 업무 표시용으로 바꾸고 공유 접근은 유지한다.

연락 정정은 요청자 확인 checkbox와 이유가 필요하다. 전화만 정정하면 인증 상태를 유지한다. 이메일 변경은 auth_version 증가·미확인 전환·관련 미사용 링크 폐기·이전 주소의 대기 알림 취소를 같은batch에서 수행한다. 목록 세션도 현재 이메일/버전을 다시 검사하므로 과거 이메일은 정정된 문의에 접근하지 못한다. 정상 미확인 건은 발송 서비스 연결 후 확인 링크 재발급을 요청할 수 있다.

삭제/복구는 관리 책임자만 가능하다. 삭제는 논리 차단이며 원문·파일 영구 파기 완료로 표시하지 않는다. 삭제/복구 시 인증 버전을 바꾸고 재확인을 요구한다. 복구는 업무 상태/분류를 보존하며 영구 제거가 시작된 대상은 거절한다. 실제 보관 기준/영구 파기/백업 삭제 반영·파일 실패 재처리는 정책 확정 후 별도 구현한다.

## 메일 안내 연결

사이트에서 답변/견적을 전달한 사실과 메일 안내 상태는 별도다. 전달과 발송 대기 이벤트를 함께 저장한다. 정상 최초 확인, 추가 설명, 담당자 변경, 정상 복구의 직원 알림을 만든다. 최초 정상 이벤트는 재인증만으로 반복하지 않는다. 담당자가 유효하면 담당자에게, 미지정/유효하지 않으면 책임자가 현황 화면에서 지정한 유효 문의 수신자에게 안내한다. 수신 설정은 기본 꺼짐이며 콘텐츠 직원은 선택/발송 대상이 아니다.

발송 직전에 삭제·현재이메일/auth_version·분류·직원 상태/역할/수신 설정을 재확인한다. 내부 binding `/v1/send` JSON은 `{to,template,link}`이며 고객 `inquiry-updated`, 직원 `staff-new-inquiry`, `staff-customer-addition`, `staff-review-needed`, `staff-assignee-change`, `staff-inquiry-recovered`를 사용한다. 본문·전화·고객 도면명·메모·첨부를 메일 payload에 담지 않는다. `Idempotency-Key`는 같은 알림 ID를 재사용한다.

서비스 응답 `{accepted:true,receipt:"제공자 접수 식별자"}`만 accepted로 기록한다. 비정상 HTTP 응답에서 `{accepted:false,definitive:true}`처럼 **확실히 발송하지 않았다고 서비스가 보장한 경우** failed로1/5/30분/2시간·총5회 이내 재시도한다. timeout/중단/불완전 응답·보장 없는500은unknown으로 보존하고 자동/일반 버튼 재발송하지 않는다. 실패 건만 이유와 현재 권한/버전으로 수동 재시도한다. 실제 제공자·반송 서명·배달 확인·unknown 결과 조회/운영 해결 화면은 후속이다. 발송 서비스 미연결/접수잠금 상태에서는 실제 발송하지 않는다.
