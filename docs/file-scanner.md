# 콘텐츠 파일 검사 연결 계약 (개발 초안)

> 환경 구분: 이 문서의 2026-10-10~11 작업·시험·계정 상태는 기존 Mac 개발 이력입니다. Ubuntu의 현재 상태는 [Mac·Ubuntu 환경 구분](development-environments.md)을 따릅니다. 역사적 `outputs/` 증빙과 `.work/` 백업·비공개 자료는 이 저장소 및 확인한 Ubuntu 작업 폴더에 미포함이며 원문은 미확인입니다.

> 현재 로컬 실제 검사 서비스와 실행 안내는 [MVP C 로컬 구현](mvp-c-local.md)이다. 아래 계약은 유지하며 ‘미선정/바인딩 미설정’은 변경 전 개발 기록이다. 운영용 배포·회사 파일 검수는 여전히 미실시다.

2026-10-11. 실제 엔진/서비스는 미선정이고 운영 시험 미실시다. 현재는 `FILE_SCANNER` 바인딩을 설정하지 않는다. 인터넷 공개 콜백, 관리자 강제 ready 전환, 모의 검사 우회 설정은 제공하지 않는다. 테스트의 모의 검사기는 메모리 시험 환경에만 있다.

## 현재 흐름

콘텐츠 초안 저장 → 대상/역할/버전/용량을 확인한 업로드 허가(30분) → 한 요청에 파일 한 개 스트리밍 → 실제 바이트 수/서명 확인 → R2 격리 원본 → validating → 별도 검사 작업 → 새 R2 안전 파일 → ready → 직원이 작성 내용을 저장하여 연결 → 공개 조건 검사.

사진 JPEG/PNG/WEBP 10MiB·대상당 20개·합계 100MiB, 자료 PDF 20MiB·선택 파일 1개, 공지 사진/PDF 10MiB·5개·합계 30MiB. 사진 대체 설명 필수. 자료 교체는 새 검사 파일을 선택하며 이전 파일은 공개 다운로드에서 제외하고 원본을 보존한다. 새 업로드는 직원당 10분 30회까지 예약한다. 파일 등록 화면의 제거는 연결을 제외하는 동작이며 공개 대표/자료 파일은 먼저 교체 또는 콘텐츠 숨김이 필요하다.

제품·모델·사례·공지에 등록한 사진은 다른 대상에서 재사용하지 않는다. 고객 도면/견적은 이 콘텐츠 업로드 대상에 포함하지 않는다. 원래 파일명·상태 등만 상태 조회에서 제공하고 저장 키·허가 토큰 해시는 제외한다. 임시/검사 중/차단 파일 다운로드는 없다. ready여도 공개 콘텐츠 저장 전에는 공개 파일로 제공하지 않는다. 비공개 미리보기는 콘텐츠 역할로 제공한다.

## 내부 서비스 계약 v1

선정한 검사 엔진을 감싼 별도 Worker 서비스에 `FILE_SCANNER`를 연결한다. 앱은 바인딩으로 `POST https://scanner.internal/v1/content`를 호출하며 R2 원본 스트림을 전송한다. 요청 `Content-Type`은 선언 및 서명 확인한 형식, `X-Scan-Contract: gnc-content-v1`이다. 이 주소는 공인 외부 API 주소가 아니며 앱에서 외부 URL/키를 입력받지 않는다.

검사기는 크기/구조/디코딩과 악성코드 검사를 실제 수행해야 한다. 사진은 최대 40메가픽셀, 위치·기타 메타데이터 제거와 재인코딩을 수행한다. PDF는 암호화·JavaScript·실행 동작·내장 파일 등 거부 조건을 실제 검사한다. 악성코드 결과 없이 성공하지 않는다. 처리 시간은 앱 요청 기준 60초이며 엔진 자체 시간/메모리 제한·동시 실행 제한은 서비스에서 추가로 설정해야 한다.

성공 응답은 200 + 안전한 결과 바이트 스트림과 아래 헤더를 제공한다. 결과 형식은 원본과 동일, 결과 크기는 12바이트 이상·예약 원본 크기 이하로 제한한다. 앱은 다시 크기/서명을 확인하고 새 무작위 키에 저장한 뒤 lease가 유효한 경우만 ready로 전환한다.

| 헤더 | 필수 값 |
| --- | --- |
| Content-Type | 원래 검증 요청과 같은 MIME |
| Content-Length | 실제 안전 파일 바이트 수 |
| X-Scan-Contract | gnc-content-v1 |
| X-Structure-Result | pass |
| X-Malware-Result | clean |
| X-Scan-Engine | 실제 엔진/버전 식별, 100자 이하 |
| X-Image-Sanitized | 사진이면 true |
| X-Image-Width / X-Image-Height | 사진이면 양의 정수·곱 40,000,000 이하 |
| X-Pdf-Safe | PDF이면 true |

거부 판정은 422(차단). 응답 오류·불완전 판정·시간 초과는 ready가 되지 않는다. 작업 lease 2분, 1분/5분/30분 후 재시도하고 4번 실패하면 운영 확인 필요 상태로 남긴다. 실제 검사 서비스가 없으면 작업을 소비하지 않고 validating을 유지한다. 공개 콘텐츠에 연결되지 않은 temporary/validating/blocked 예약은 24시간 만료 대상으로 격리 객체만 제거한다. 연결 원본·교체본·복구 가능한 삭제 파일의 영구 정리는 회사 보관 정책 확인 후 별도 구현한다.

매분 예약 작업을 구성했으며 로컬에서는 별도 예약 작업 호출이 필요하다. 실제 cron·서비스 바인딩 운영 연결은 배포 이후 검수해야 한다. 실제 악성 파일/암호화 PDF/고해상도·동시 업로드 검수, 썸네일 생성·보관 정리 재시도/실패 보고, 검사 판정 상세 이력은 남은 범위다. 기본 서명 확인은 악성코드/디코딩 성공으로 간주하지 않는다.

[Cloudflare R2 Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/), [내부 서비스 바인딩](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/http/)을 참고했다. 실제 앱 기능 시험과 제공자의 보증 범위를 구분한다.
