# 로컬 D1·R2 백업과 격리 복원

2026-10-14. 로컬 개발 저장소용입니다. Cloudflare 원격 자원·운영 데이터에는 연결하지 않습니다.

## 저장 경로와 포함 범위

기본 Wrangler 저장소는 저장소 루트의 `.wrangler/state/v3/`입니다. `--persist-to`로 다른 경로를 선택했다면 해당 경로의 `v3/`를 `--state`로 지정합니다.

| 경로 | 백업 여부 |
| --- | --- |
| `d1/miniflare-D1DatabaseObject/*.sqlite` | D1 DB와 내부 메타데이터 포함 |
| `r2/miniflare-R2BucketObject/*.sqlite` | R2 객체 목록·메타데이터·multipart 상태 포함 |
| `r2/<bucket>/blobs/*` | 실제 객체 및 multipart 파일 포함 |
| SQLite WAL/SHM/journal 파일 | 직접 복사하지 않음. SQLite backup API가 커밋된 WAL 내용까지 DB 스냅샷에 반영 |
| KV·캐시·관측 로그·다른 저장소 | 제외 |
| `.dev.vars*`, `.env*`, 인증서·개인키·클라우드 로그인 설정 | 제외 |

백업 기본 위치는 `.local-backups/<UTC 시각>-<무작위 ID>/`이며 원본 Wrangler 저장소와 분리되어 있습니다. `.local-backups/`, `.local-restore-tests/`는 Git에서 제외합니다. `--output`으로 다른 디스크의 전용 백업 폴더를 지정할 수 있습니다. 외부 경로를 사용할 때도 Git 저장소에 자료를 추가하지 않습니다.

백업 디렉터리에는 `state/v3/`와 `manifest.json`만 저장합니다. manifest는 백업 완료 후 마지막으로 기록하며, 없는 백업은 미완성으로 취급합니다. 백업 시각(UTC), 원본 경로, 소스 커밋, 작업 트리 변경 유무, Node·pnpm 요구 버전, 실제 Wrangler·Python·SQLite 버전, 잠금 파일·설정·마이그레이션 체크섬, 모든 DB의 스키마·테이블별 행 수·행 내용 해시, R2 객체 목록·객체별 SHA-256, 모든 저장 파일 크기·SHA-256과 복원 안내를 포함합니다. 설정 파일은 체크섬만 기록하고 내용을 복사하지 않습니다.

디렉터리 0700·파일 0600과 umask 077을 사용합니다. **비밀 설정 파일을 제외해도 DB 안의 계정·세션·문의와 R2 파일 자체는 민감할 수 있습니다.** 백업은 암호화되지 않으므로 개인 전용 경로에 보관하고 공개하거나 Git에 추가하지 않습니다.

## 일관된 백업 명령

Python 3.11 이상 표준 라이브러리만 사용합니다. 검사 서비스의 Pillow·pikepdf 가상환경과 무관합니다. 프로젝트에서 `nvm use`로 고정 버전을 선택합니다.

1. 이 프로젝트의 `pnpm dev`와 `pnpm dev:https` 터미널에서 Ctrl+C로 중지합니다. 다른 프로젝트 서버를 중지하지 않습니다. D1/R2 명령·업로드·마이그레이션·데이터 생성 작업도 종료하고 백업이 끝날 때까지 시작하지 않습니다.
2. 다음 명령으로 백업합니다.

```sh
python3 scripts/local-backup.py backup --quiesced
# 다른 백업 위치가 필요할 때:
# python3 scripts/local-backup.py backup --quiesced --output /별도/전용/백업폴더
```

3. `ok: true`와 출력된 `backup` 경로를 확인합니다. 실패 시 해당 백업을 사용하지 않습니다. 완료 manifest가 없는 중단된 폴더는 검사 후 수동 정리하며 스크립트는 자동 삭제하지 않습니다.
4. 원래 사용한 명령으로 서버를 다시 실행합니다. 공개 미리보기는 `pnpm dev`입니다. HTTPS·검사 서비스를 쓰던 환경은 해당 환경의 원래 실행 방법을 따릅니다.

`--quiesced`는 **모든 원본 쓰기 작업이 중지되었음**을 사용자가 확인하는 옵션입니다. 기본 저장소에서는 8787/8788 포트와 이 프로젝트 폴더의 Wrangler/Miniflare/workerd 프로세스도 검사해 실행 중이면 거부합니다. 다른 포트·경로·직접 SQLite 접근 등 모든 쓰기 프로그램을 자동 탐지하는 기능은 아니며 특히 `--state`로 별도 저장소를 선택할 때는 직접 확인해야 합니다.

D1·R2는 하나의 트랜잭션으로 묶을 수 없으므로 서버를 켠 채 DB만 복사하는 방식은 사용하지 않습니다. 모든 쓰기 작업을 중지한 상태에서 각 SQLite DB를 backup API로 복사하고 R2 파일을 복사합니다. 원본→백업→원본 재확인의 스키마·행 수·내용 해시·R2 목록·파일 해시가 일치해야 백업을 완료합니다. 원본 DB를 checkpoint하거나 데이터를 추가하지 않습니다.

## 원본을 덮어쓰지 않는 복원·검증

실제 출력된 백업 경로를 아래 `백업폴더` 대신 사용합니다. `--destination`은 **존재하지 않는 새 폴더**여야 합니다.

```sh
python3 scripts/local-backup.py restore .local-backups/백업폴더 \
  --destination .local-restore-tests/restore-new

python3 scripts/local-backup.py verify .local-backups/백업폴더 \
  --state .local-restore-tests/restore-new/v3
```

복원은 먼저 백업의 파일 목록·크기·SHA-256·DB 무결성·외래키·스키마·행 수·행 내용·R2 객체 목록과 내용을 검증합니다. 검증된 파일만 새 `v3/`에 복사하고 동일 검사를 다시 수행합니다. 복원 폴더에 `verification.json`을 남깁니다. 기존 폴더, 원본과 겹치는 경로, 실제 `.wrangler/` 아래 경로로는 복원하지 않습니다. 손상된 백업과 symlink 저장 파일도 거부합니다.

`verify`는 **복원된 런타임을 시작하기 전** 실행합니다. 실행 후에는 SQLite 내부 메타데이터 등이 바뀔 수 있어 원래 파일 체크섬과 같다는 보장이 없습니다. 객체의 크기와 실제 blob 존재 여부도 검사하며 multipart 객체는 part 순서로 결합한 SHA-256을 비교합니다.

추가 화면 시험이 필요하면 manifest의 소스 커밋·잠금 파일·Wrangler 버전과 같은 코드로, 원래 서버와 다른 포트에서 복원 경로를 명시합니다.

```sh
# 격리된 복원 자료만 사용. 비밀 설정이 없는 별도 코드 체크아웃에서 실행 권장.
pnpm exec wrangler dev --local --env='' --persist-to .local-restore-tests/restore-new \
  --ip 127.0.0.1 --port 8791 --inspector-port 9241
```

복원 폴더를 기존 `.wrangler/state/`로 바꿔치기하는 자동 명령은 제공하지 않습니다. 실제 데이터 복구 전환은 계정·세션 회수, 최신 권한·삭제 기록 재적용 등을 검수한 별도 작업으로 진행해야 합니다.

## 가상 데이터 시험과 이번 검증

```sh
nvm use
node scripts/test-local-backup.mjs
```

이 명령은 `.local-restore-tests/fixture-*/` 안에 설치된 Miniflare로 새 D1·R2를 만듭니다. 모든 마이그레이션을 가상 DB에 적용하고 공지 1건 및 UTF-8 텍스트·이진·빈 파일 3개만 등록합니다. 실제 직원·고객 정보와 비밀 설정은 사용하지 않으며 원본 `.wrangler/`에는 쓰지 않습니다. 백업·복원·체크섬 비교 후 새 workerd에서 가상 공지 조회·R2 목록·파일 바이트를 다시 확인합니다. 확인 미동의·기존 경로·실제 저장소 경로·손상 백업 복원·손상 백업 검증 거부도 시험합니다. 시험 자료는 재검토할 수 있도록 제외 경로에 남깁니다.

## 남은 한계

- **같은 컴퓨터의 백업은 컴퓨터 고장에 대비한 외부 백업과 별개입니다.** 별도 장치/계정에 암호화된 사본을 보관하고 복원 시험·보관 주기·삭제 정책을 마련해야 합니다. 이번에는 외부 백업을 구성하지 않았습니다.
- 현재 Wrangler/Miniflare v3 저장 형식에 의존합니다. 버전 변경 시 호환성을 다시 검증해야 합니다. 원격 D1 export/복원, R2 버전 관리 및 운영 복구 절차를 대신하지 않습니다.
- 체크섬은 손상 탐지용이며 공격자가 manifest까지 바꾸는 것을 막는 서명이나 외부 신뢰 증명이 아닙니다.
- 중지 시간이 필요합니다. 대규모 DB의 행 해시 정렬은 메모리를 사용하며 파일 읽기·해시·여러 복사에 시간과 공간이 필요합니다. 대용량·진행 중 multipart 업로드·여러 버전/OS의 복구는 추가 검수 대상입니다.
- 계정·세션·발송 대기·삭제 이전 기록을 포함하는 DB를 실제 서비스에 되돌릴 때의 처리 정책은 아직 구현하지 않았습니다. 복원 자료로 고객 접수·이메일·파일 검사·예약 업무를 자동 실행하지 않습니다.
