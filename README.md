# 지엔씨쿨링 홈페이지 개발 환경

이 저장소 루트에서 개발합니다. 기존 Mac 프로젝트의 `sources/`, `outputs/`, `.work/` 자료는 이 저장소에 포함되지 않았습니다. 현재 환경 상태는 [Mac·Ubuntu 환경 구분](docs/development-environments.md)을 참고하세요.

## 실행

Mac과 Ubuntu 모두 **Node.js 24.21.0 / pnpm 12.11.2**를 사용합니다. `.nvmrc`, `package.json`의 `engines`와 `packageManager`에 버전을 고정했습니다. nvm이 설치된 셸에서 저장소 루트로 이동한 뒤 다음 순서로 실행합니다.

```sh
# 1. 버전 선택 (해당 Node.js가 없으면 nvm install)
nvm use
corepack enable pnpm
node --version  # v24.21.0
pnpm --version  # 12.11.2

# 2. 잠금 파일 기준 패키지 설치
pnpm install --frozen-lockfile

# 3. UI 자산 빌드
pnpm ui:build

# 4. 로컬 DB 마이그레이션 (기존 데이터가 있으면 먼저 백업)
pnpm db:local

# 5. 코드 검사
pnpm check

# 6. 공개 화면 개발 서버 실행
pnpm dev
```

새 터미널의 기본 Node.js도 맞추려면 각 컴퓨터에서 `nvm alias default 24.21.0`을 실행합니다. 이미 열려 있는 셸은 `nvm use`로 전환합니다. Corepack이 없는 환경은 먼저 Corepack을 준비해야 합니다. `pnpm install --frozen-lockfile`은 프로젝트 의존성 버전을 갱신하지 않습니다. pnpm 12의 도구 버전 잠금 메타데이터는 이번 버전 고정에 맞춰 잠금 파일에 추가되었습니다.

메인 미리보기는 http://127.0.0.1:8787/, 스타일 가이드는 http://127.0.0.1:8787/style-guide 입니다. 정적 자산이 Git에 포함되어 있어도 UI 소스를 바꾼 뒤에는 `pnpm ui:build`가 필요합니다.

이번 2026-10-14 버전·문서 정비에서는 위 실행 절차 중 DB 마이그레이션을 다시 실행하지 않았습니다. 기존 DB·직원 계정·비밀 설정을 유지했습니다.

`pnpm check`는 코드 검사, `pnpm build`는 실제 배포 없이 Cloudflare 실행 파일 생성 여부를 확인합니다.

`pnpm test`는 권한 정책·비공개 경로 차단과 제품 구조·공개 조회의 개발 자동 시험입니다. 실제 로그인·업무·외부 서비스 검수를 대신하지 않습니다.

[현재 구현 현황·개발 순서·시험 기록](docs/implementation-plan.md)

[로컬 D1·R2 백업·격리 복원 명령과 검증](docs/local-backup.md): 데이터 변경 전에 프로젝트 쓰기 작업을 중지하고 백업합니다. 기본 백업은 Git에서 제외한 `.local-backups/`에 저장하며 복원은 새 경로에만 수행합니다.

[MVP C 전용 이메일·비밀번호 로그인과 로컬 HTTPS·실제 파일 검사](docs/mvp-c-local.md): 현재 사용자 선택을 반영한 실행·초대 안내입니다. 기존 OIDC 연결 문서는 이전 제안입니다.

**환경별 상태를 구분합니다.** Mac의 2026-10-11 최신 기록에는 로컬 책임자 활성화와 실제 ClamAV 검사 검증이 남아 있습니다. Ubuntu의 2026-10-14 점검에서는 직원·초대·비밀번호·세션이 모두 0건이며, 인증 비밀 설정·HTTPS 인증서·검사 가상환경·ClamAV 자료는 준비되지 않았습니다. Mac의 로컬 계정·데이터·비밀값은 Git으로 옮겨지지 않습니다.

2026-10-14 후속으로 [Mac·Ubuntu 로컬 파일 검사 환경](docs/local-scanner.md)과 [Ubuntu HTTPS·가상 직원·관리자 업로드 통합 검증](docs/local-https-demo.md)을 준비했습니다. `pnpm scanner:local`, `pnpm dev:https`는 Mac의 기존 경로를 보존하고 Ubuntu에서는 전용 경로를 사용합니다. 점검 당시 미준비 기록은 이 후속 작업 전 상태입니다. Ubuntu의 가상 직원·시연 콘텐츠는 별도 `.local-https/state/`에 있고 기존 `.wrangler/state/` 및 실제 책임자 계정과 구분합니다. 로그인 주소는 `https://localhost:8788/admin/login`이며 시연 홈페이지는 `https://localhost:8788/`입니다. 공개 HTTP 미리보기와 고객 실제 접수 잠금은 유지합니다.

## 구성

- public/: 화면 스타일 등 정적 자산
- src/: Cloudflare Workers 프로그램·공개 화면·페이지 설정·제품 조회
- migrations/: D1 테이블 변경 기록
- docs/: 개발 순서와 운영 연결 계획
- .wrangler/: 로컬 D1·R2 시험 데이터. Git에 포함하지 않습니다.

현재는 로컬 개발 전용입니다. wrangler.jsonc의 데이터베이스 ID는 로컬용 임시 값이며 실제 배포에 사용할 수 없습니다. Cloudflare 브라우저 로그인은 완료했으며 개발용 D1·비공개 Standard R2만 생성했습니다. 개발 D1의 기존 마이그레이션 12개를 검증·적용했습니다. 배포·도메인 변경은 수행하지 않았습니다.

[Cloudflare 개발 D1·R2 연결 준비](docs/cloudflare-development-plan.md): 2026-10-14 로그인 후 Ubuntu Wrangler 인증·단일 계정을 확인했습니다. 사용자의 R2 구독 활성화 후 지정한 개발 D1·R2를 각각 1개 생성하고 재조회했습니다. 후속 마이그레이션으로 개발 D1은 앱 테이블 41개·기본 제품군 3건·나머지 업무 데이터 0건이며, R2는 파일 0개·Standard·공개 URL 비활성·사용자 지정 도메인 없음입니다. 요금제·결제 상세는 미확인입니다. 로컬 설정을 보존하는 개발·운영 분리 템플릿과 읽기 전용 점검, 생성 계획·비용·선행 조건을 마련했습니다. 템플릿의 공개 접근·직원 인증·고객 접수·검사·메일 연결은 닫혀 있습니다. 개발 자원 생성과 D1 마이그레이션을 완료했으며 추가 업무 데이터 입력·배포는 실행하지 않았습니다.

[개발 D1 마이그레이션 검토·적용·검증](docs/development-d1-migrations.md): 격리 로컬·원격 전체 스키마 비교, 이력 12건·미적용 0건·무결성 확인과 재점검 명령을 기록했습니다.

[개발 미리보기 배포 준비](docs/development-preview.md): 실제 개발 D1·R2 바인딩의 dry-run과 Access 기반 접근 제한·업무 기능 잠금·연결 확인·로그·롤백 절차를 준비했습니다. 실배포와 URL/Access 활성화는 아직 하지 않았습니다.

## 개발과 공개 순서

1. 권한 공통 기반과 미인증 경로 차단을 마련합니다. 권한 기반 개발 시험을 완료했습니다.
2. 메인·정적 페이지와 제품 목록·상세 화면 및 데이터 구조를 구현합니다.
3. 제품·사례·자료·공지 관리와 직원 인증을 구현합니다.
4. 고객 접수·본인 확인·답변·견적·첨부 권한을 구현합니다.
5. Cloudflare 계정 연결 후 개발용 D1·R2를 별도로 생성합니다.
6. 비공개 시험 주소에서 이메일·스팸·자료 접근·복구와 역할별 업무를 확인합니다.
7. 운영용 D1·R2와 비밀값을 별도로 설정하고 검수·오픈 확인 후 기존 도메인을 전환합니다.

실제 고객 개인정보를 로컬 시연 자료나 Git 저장소에 넣지 않습니다. 개발·시험·운영의 데이터와 파일은 분리합니다. 고객 데이터·비공개 파일 API는 인증과 권한 검증이 완성되기 전 제공하지 않습니다.

## 기존 Mac 개발 이력

아래 기록은 2026-10-10~11 Mac 개발 당시의 상태와 시험 결과를 보존한 것입니다. Ubuntu에 데이터·인증·검사 환경이 준비되었다는 의미가 아닙니다. 당시 `outputs/` 증빙과 `.work/` 백업·비공개 자료는 이 저장소 및 확인한 Ubuntu 작업 폴더에 **미포함**이며 원문 증빙은 미확인입니다. 현재 준비 상태는 [환경 구분 문서](docs/development-environments.md)를 따릅니다.

## 공개 페이지·제품 조회 현황

상단 6개 메뉴와 정적 11페이지, `/products` 목록·`/products/{id}` 상세를 구현했습니다. 실제 회사정보와 제품 자료는 확인 전 준비 중이며 시공 사례·자료·문의 접수는 준비 안내입니다. 공지는 아래 3단계에서 DB 조회로 연결했습니다.

`0002_product_structure.sql`은 기존 products를 legacy_products로 보존하고 새 제품군·제품·모델·사양 구조를 만듭니다. 기존 시험 자료는 작성 중 상태로 이동하고 원본 JSON 사양은 보존합니다. 로컬 DB에는 migration을 적용했으며 실제 제품/사진을 추가하지 않았습니다.

공개 제품은 사용 중인 상위 분류·공개 상태·설명·검증된 공개 대표 사진·대체 설명 조건을 적용합니다. 사진 응답도 현재 공개 상태를 매 요청 확인하며 저장 키는 제공하지 않습니다. 관리자 사진 등록·검사 처리와 실제 콘텐츠 운영은 후속 작업입니다.

## 파일·공개 연결 진행 현황 (2026-10-11)

사진/PDF 업로드와 검사 대기·재시도, 제품/모델/사례/공지 사진과 자료 PDF 연결, 파일을 포함한 미리보기, 사례·자료 공개 목록/상세를 추가했습니다. 검사 완료 후 직원이 저장해야 연결되며 숨김·교체 시 공개 다운로드를 차단합니다.

**실제 검사 엔진은 미선정**입니다. FILE_SCANNER 미설정에서는 업로드가 검사 대기로 남습니다. 모의 검사 시험 통과를 실제 악성코드 검사·파일 운영 완료로 표시하지 않습니다. 로그인 계정도 아직 미정이므로 관리 화면은 실제 계정 연결 이후 사용 가능합니다.

자동 시험45개, 모의 브라우저 업무와 격리된 Workers/R2 스트리밍 시험을 완료했습니다. 상세 범위·한계는 파일 개발 검증 기록 (원래 경로: `../outputs/검증/20261011-content-files/검증기록.md` · 자료 미포함, 원문 미확인), 연결 규격은 [검사 서비스 계약](docs/file-scanner.md)을 참고하세요. 로컬 예약 작업은 수동 호출로 확인해야 하며 운영 서비스/예약 작업 배포는 수행하지 않았습니다.

## 직원 로그인 연결 준비 (2026-10-11)

인증 서비스는 아직 미정입니다. 일회성 최초 관리자 초대·재발급과 실제 OIDC 확인 후 활성화, 로그인/로그아웃 이력·만료 세션 정리를 추가했습니다. 현재 실제 직원 계정은 등록하지 않았으며 로그인 화면은 준비 중입니다.

`pnpm auth:check`는 비밀값을 표시하지 않고 로컬 설정/Discovery를 확인합니다. `pnpm auth:initial-local --create` / `--reissue`는 확정한 개인 계정 정보를 표준 입력으로 받아 로컬에만 초기 초대를 준비합니다. 현재 미설정에서는 실행할 수 없습니다. [서비스 연결·초기 관리자 등록 안내](docs/staff-auth-setup.md)를 먼저 확인하세요. 실제 서비스·HTTPS 주소·계정 소유 검수가 완료되기 전에는 로그인 완료로 기록하지 않습니다.

## 고객 문의 연결 준비 (2026-10-11)

문의 저장·동의/연결 기록, 이메일 본인 확인·본인 문의 조회, 서버 스팸 검사·반복 제한, private 첨부 검사/귀속/조회와 메일 발송 대기 구조를 추가했다. 가상 개발 시험74개와 신청부터 본인 상세까지의 브라우저 시험을 통과했다.
